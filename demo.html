传统模式

传统 UI 组件：强耦合一体设计

组件 = 逻辑 + 样式 + DOM 结构（三者强绑定）

✅ 优点

  • 开箱即用，5 分钟出页面
  • 上手极快，文档齐全
  • 适合后台管理类标准场景

❌ 代价

  • 业务越复杂，Override 越多
  • 维护成本指数级上升
  • 升级版本 = 回归测试噩梦
核心痛点

我们每天都在面对的困境

传统组件库的三大致命问题

🔴 样式失控

深度覆盖、!important 地狱
主题难以统一
5 层嵌套选择器是常态

🔴 组件黑盒

Table/Select/DatePicker
内部逻辑封闭
小改样式 → DOM 崩、状态崩、升级崩

🔴 设计系统割裂

设计师需求与前端实现
无法对齐
一处修改，全局受影响

真实案例

样式覆盖噩梦：Ant Design 真实场景

「只是想改个 Select 的圆角和颜色」

❌ Ant Design 样式覆盖
/* 改个 Select 圆角要写这么多 */ .ant-select .ant-select-selector { border-radius: 8px !important; border-color: #7c5cfc !important; } .ant-select-focused .ant-select-selector { box-shadow: 0 0 0 2px rgba(124,92,252,0.2) !important; } .ant-select-dropdown { border-radius: 12px !important; }

3 个 !important，且升级版本可能失效

✅ shadcn/ui 同样效果
<!-- 声明式，零覆盖 --> <Select> <SelectTrigger className="rounded-lg border-[#7c5cfc] focus:ring-2 focus:ring-[#7c5cfc]/20" /> <SelectContent className="rounded-xl" /> </Select>

0 个 !important，完全可控

?

组件到底应该负责什么？

答案：只负责逻辑与交互，不负责视觉样式

→ 逻辑与视觉必须彻底解耦

核心概念

Headless UI：无头组件

只提供行为，不提供样式

✅ 负责

  • 状态管理（open/close/selected）
  • 键盘交互（Tab/Enter/Esc）
  • 无障碍访问（ARIA 属性）
  • 焦点管理（Focus Trap）

❌ 不负责

  • CSS 样式
  • UI 风格 / 主题
  • 固定 DOM 结构
  • 任何视觉决策

核心价值

Headless UI 为什么是 Design System 基础？

四大核心优势 + 真实收益

  • 逻辑复用：一套逻辑，多套视觉（Web / RN / 小程序）
  • 无障碍原生内置：ARIA / Focus Trap / Keyboard Nav 开箱即用
  • 无样式入侵：完美适配团队设计规范，零覆盖
  • 真正实现逻辑与视觉分离，升级无惧
真实案例

Radix UI 无障碍覆盖

Dialog 组件内置 Focus Trap + Escape 关闭 + Scroll Lock + ARIA 标注，
传统组件库需自行实现，平均 200+ 行 无障碍代码，Radix 0 行

Tailwind

Tailwind：不是原子 CSS，是 Design Token Runtime

class="p-4 rounded-xl text-sm" 背后是什么？

spacing scale

间距体系

p-4 → 16px

radius scale

圆角体系

rounded-xl → 12px

typography scale

字体体系

text-sm → 14px

用统一约束替代无限制自由

代码对比

同一个卡片组件：CSS vs Tailwind

实现一个带 hover 效果的产品卡片

🔴 传统 CSS
/* card.css - 3个文件，42行 */ .product-card { display: flex; flex-direction: column; padding: 24px; border-radius: 16px; background: #1e1e2c; border: 1px solid rgba(255,255,255,0.1); transition: all 0.2s; } .product-card:hover { border-color: #7c5cfc; box-shadow: 0 4px 20px rgba(124,92,252,0.15); } .product-card__title { ... } .product-card__price { ... } // + JSX 中 className 引用 // + 命名冲突风险 // + 设计师改 24→20px 要全局搜索
🟢 Tailwind
<!-- 1个文件，0行CSS --> <div className="flex flex-col p-6 rounded-2xl bg-card border border-white/10 hover:border-accent hover:shadow-[0_4px_20px_rgba(124,92,252,0.15)] transition-all duration-200"> <h3 className="text-lg font-semibold text-white">...</h3> <span className="text-2xl font-bold text-accent"> ¥199 </span> </div> // 设计师改 p-6 → p-5，一处即改 // 零命名冲突、零全局搜索
设计系统

Tailwind = 设计系统运行时

tailwind.config.js — 设计师与开发者的唯一真相源

// tailwind.config.js — 设计 Token 一键映射 module.exports = { theme: { extend: { colors: { // 设计师色板 → 代码 Token，零误差 primary: '#7c5cfc', // 主色 surface: '#16161f', // 卡片背景 danger: '#f44b5c', // 错误态 success: '#3dd68c', // 成功态 }, borderRadius: { lg: '12px', // 统一圆角 xl: '16px', }, spacing: { safe: 'env(safe-area-inset-top)', } } } } // 改 primary 颜色 → 全站秒级生效
"

Tailwind 并不是在消灭 CSS，
而是在消灭失控的 CSS。

范式革新

shadcn/ui：不是组件库，是资产方案

核心逻辑：不安装依赖，直接复制源码到项目

🔴 传统组件库

  • npm install 安装
  • 黑盒：源码不可控
  • 你适配组件库
  • 升级 = 风险事件

🟢 shadcn/ui

  • npx shadcn add 复制
  • 白盒：源码即你代码
  • 组件库适配你
  • 无升级，无版本锁

UI 从「第三方依赖」→「团队自有资产」

代码对比

shadcn/ui 安装 vs 传统安装

同样是加一个 Button 组件

🔴 传统方式
# 安装整个 UI 库 $ npm install antd # 引入 Button import { Button } from 'antd' import 'antd/dist/reset.css' // node_modules 增加 12MB+ // Bundle 增加 ~85KB (gzip) // 只用了 Button，却加载了整个库 // 样式覆盖：覆盖 default → primary <Button type="primary" className="my-custom-btn"> 提交 </Button>
🟢 shadcn/ui

价值总结

最大创新：Ownership（所有权）

组件所有权回归业务团队，而非被第三方库绑架

🔴 传统：租户模式

  • 组件归第三方所有
  • 你能用，但不能改核心
  • 版本升级 = 被动接受变更
  • Breaking Change 随时可能来

🟢 shadcn/ui：业主模式

  • 组件归你的项目所有
  • 源码在你项目里，随便改
  • 无版本依赖，无升级压力
  • 变更完全由你掌控
"

shadcn/ui 最大的创新，
不是组件，而是ownership。

AI 赋能

AI Coding：重新定义 UI 开发

AI 最擅长 vs AI 最头疼

✅ AI 最擅长生成

  • Tailwind class：p-4 rounded-xl
  • 标准化结构：组件 + Token
  • 可预测、可推理的代码
  • 无歧义的设计 Token 映射

❌ AI 最头疼生成

  • 自定义 CSS 命名：.my-wrapper
  • 深层嵌套覆盖：.a .b .c .d {}
  • 语义不明的 BEM 变体
  • 组件库内部样式结构

Tailwind 是 AI 时代最友好的 UI DSL
可预测、可生成、可推理、可批量产出

AI 实战

同一个需求：AI 生成代码质量对比

Prompt：「创建一个带搜索和筛选的用户管理表格」

🔴 Ant Design 方案
// AI 需要理解： // 1. antd Table 的 columns 配置 // 2. antd Form 的 Field 绑定 // 3. 样式覆盖选择器层级 // 4. 主题变量 token 体系 const columns = [ { title: '姓名', render: (_, r) => <Space> <Avatar src={r.avatar} /> {r.name} </Space> }, // ...5+ 列配置 ] // + 样式覆盖文件 80+ 行 // + 主题定制 ConfigProvider // 结果：AI 多次重试，样式不一致
